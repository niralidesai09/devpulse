SumitPM, code review automation startup

Sets what to watch

Adds, edits or pauses topics and keywords on /topics (admin passcode). No code changes. Can press Run now for a live demo.

Asks anytime

“Ask the Pulse”: a question is answered only from stored discussions, with links. Nothing relevant means “not enough data”.

Human decision

Approves new topics

The radar suggests pain points no topic covers. Sumit taps Approve & monitor or Reject. Rejected ideas never come back.

Human decision

Takes it to the sprint

Reads the brief before the afternoon engineering sync, opens the evidence, and chooses what goes into Monday’s sprint planning.

Groundswell appNext.js on Vercel

Starts the run

The cron route checks the CRON_SECRET; Run now checks the admin cookie. Refuses to start if a run is already going.

Collects & cleans

4 adapters in parallel, last 7 days, keyword match on title + body. Rejects off-site links, dedupes by id and URL, keeps the top 300. A failed source marks the run partial; the run continues.

Counts last week fairly

Smart baseline: Hacker News exact-phrase matches, this week vs the 7 days before. Under 5 in total → “too few to compare”, never a fake %.

Scores in code

Mentions, unresolved %, severity, trend. Opportunity Score = frequency × growth × unresolved × severity, top topic = 100. Every factor stored for “Why this score?”.

Checks the AI

Turns evidence ids into real thread links, strips any URL Gemini typed, flags numbers not in its input. Radar ideas need ≥ 2 real threads.

Shows the answers

Overview answers the three questions: most discussed (with counts), up or down vs last week, still unresolved. Plus Trends, Opportunities and a searchable Evidence feed.

GeminiFlash, structured JSON

Receives

Posts in batches of 25 plus the topic list, from the server only. Post text is marked as untrusted, so instructions inside it are ignored.

Classifies each post

Topic, “other” or irrelevant · one-line pain point · unresolved + reason · sentiment · severity 1–5 · competitors named. Checked against a schema; retried once if invalid.

Spots new pain

Clusters “other” posts into up to 4 suggested topics with keywords and evidence.

Explains, never counts

Writes the brief’s commentary, citing evidence ids only. Tables and numbers come from code. Names likely sales objections with a suggested response.

SupabasePostgres database

Topics

Monitored topics and their keywords. Editable from the app, so the watch list evolves with the product.

Runs, posts

One row per run with per-source status. Each post keeps source, id, URL, published and retrieved time.

Read by the server only

Row-level security: the public key can only read. Writes need the service-role key on the server. Full-text index powers Ask.

Topic stats

Counts, trend and every score component per topic per run, so this week can be compared with last week.

Briefs, suggestions

The brief, opportunities, objections and email status; suggested topics waiting for Sumit.

Outside servicesLive APIs, cron, email

Vercel Cron

Every Friday 08:00 IST (02:30 UTC) it calls the weekly run.

4 public communities

Hacker News (Algolia) · GitHub Issues · Stack Overflow · DEV.to. Live data only, nothing mocked.

Resend email

Delivers the brief to Sumit’s inbox the same morning, with links to every cited thread.

Code counts

Every number, trend and score is computed in code from stored data. Gemini cannot change one.

Gemini reads and explains

It classifies posts and drafts the commentary, citing real threads. It never invents links.

Sumit decides

He chooses what to monitor and what reaches the sprint. The tool stops at evidence.
